# IPTV 智能测速与 M3U 调度说明文档

本文档详细说明了系统如何利用多个客户端上报的测速结果，以及在用户获取 M3U 订阅时，系统是如何提供“针对性”和“定制化”播放列表的。

## 一、 客户端众包测速机制 (Crowdsourced Speed Testing)

系统通过各个客户端（浏览器）发起的探针测试，收集不同地区的真实播放数据。针对这些多客户端上报的数据，系统做出了以下几点充分利用：

1. **可靠度统计 (Reliability Scoring)**
   - 系统会记录每个播放源的历史测试总次数 (`testCount`) 和成功次数 (`successCount`)。
   - 通过计算 `(successCount / testCount) * 100%` 得出该源的“可靠度”。即使某次偶然测速失败，只要历史可靠度高，依然能客观反映该源的长期质量。

2. **延迟平滑处理 (EMA Latency)**
   - 采用指数移动平均 (Exponential Moving Average) 算法处理延迟数据：`新延迟 = 旧延迟 * 0.7 + 本次测速延迟 * 0.3`。
   - 这种算法能够有效过滤掉某一次网络波动带来的异常高延迟或低延迟，提供更平滑、真实的平均延迟参考。

3. **智能归属地与运营商发现 (Smart ISP/Province Discovery)**
   - 很多从网络采集到的直播源缺乏“省份”和“运营商(ISP)”标签。
   - 当某个客户端上报了一个极低延迟（<100ms）且可用的测速结果时，系统会**自动推断**该播放源极有可能与该客户端处于同省份或同运营商。
   - 系统会自动将该客户端的 ISP 和 省份信息补充到该播放源的属性中，从而通过众人拾柴火焰高的方式，不断完善库内源的归属地数据。

## 二、 针对性的 M3U 列表分发 (Targeted M3U Export)

在获取 M3U 播放源时（例如在 TV 端配置订阅链接），系统会根据请求者的网络环境，**自动生成千人千面的针对性播放列表**。

### 1. 自动 IP 嗅探与环境匹配
当播放器请求 `/api/export/m3u` 接口时，如果没有手动指定网络参数，服务端会自动：
- 读取请求头中的 `X-Forwarded-For`、`X-Real-IP` 或真实连接 IP。
- 通过内置逻辑解析出请求者所在的**省份**和**运营商**（例如：广东、电信）。
- 针对性地在每个频道中，**优先挑选并排序**最适合该当前环境的播放源。

### 2. 播放源优选策略 (`getPlayableSources`)
对于每一个电视频道，系统会对它拥有的多个播放源进行打分排序，优先级从高到低如下：
1. **完全匹配**：ISP 和省份都与客户端一致，且状态为 active（最高优先级）。
2. **ISP 匹配**：运营商一致（例如都是电信），且状态为 active。
3. **状态可用**：不限地区，只要当前状态是 active 且延迟较低。
4. **未知状态**：未测试过的源作为备用。
5. **失效源**：状态为 inactive（沉底，或者可以通过参数直接剔除）。

### 3. 支持的手动控制参数
除了自动嗅探，您还可以在 M3U/TXT 订阅链接后拼接参数来强制进行针对性导出：

**接口地址**: 
- `GET /api/export/m3u` 
- `GET /api/export/txt`

| 参数名     | 说明                                                         | 示例 |
| ---------- | ------------------------------------------------------------ | ---- |
| `isp`      | 强制指定运营商，如“电信”、“联通”、“移动”           | `?isp=电信` |
| `province` | 强制指定省份，如“北京”、“广东”                               | `?province=广东` |
| `category` | 仅导出特定分类（分类 ID 或名称）                             | `?category=央视` |
| `status`   | 仅导出特定状态的源，推荐设置为 `active` 以过滤掉失效源       | `?status=active` |
| `limit`    | 每个频道最多保留几个源（避免单个频道源太多导致列表过长）     | `?limit=3` |
| `ip`       | 模拟一个客户端 IP 进行解析环境                               | `?ip=114.114.114.114` |

**订阅链接组合示例**：
- **家庭日常订阅** (仅导出可用源，且每个频道最多挑选最匹配的前 3 个源)：
  `http://<您的域名>/api/export/m3u?status=active&limit=3`
- **强制调度** (强行获取“上海电信”环境的最佳排序，并只看央视)：
  `http://<您的域名>/api/export/m3u?isp=电信&province=上海&category=央视`

### 总结
通过众包测试收集数据 + 订阅端 IP 智能推断，系统可以在每次终端请求 M3U 列表时提供**量身定制的源排序**。这不仅能有效降低卡顿、提高秒开率，也能在某些源失效时，通过平滑的可靠度算法避免错杀，从而实现最佳的观看体验。
